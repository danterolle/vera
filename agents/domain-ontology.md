# VERA Domain Ontology & Evidence Contracts

> **Target Audience**: AI Agents and Engineers working on evidence extraction, claim validation, or threat intelligence integrations in VERA.

## 1. Threat Intelligence Taxonomy

VERA integrates standardized open cybersecurity taxonomies to ensure semantic interoperability:

```text
┌─────────────────────────────────────────────────────────────┐
│                      ATT&CK Enterprise                      │

│          ▲                    ▲                             │
│          │                    │                             │

└──────────┼────────────────────┼─────────────────────────────┘
           │                    │
┌──────────▼────────────────────▼─────────────────────────────┐
│                   Vulnerability Catalogs                    │

│          │                         ▲                        │
│          ▼                         │                        │

│   CISA KEV Catalog                 (CAPEC-115)              │
│   NVD CVSS Metrics                                          │
└─────────────────────────────────────────────────────────────┘
```

### 1. Authoritative Data Sources
- **CVE.org**: CNA-authored CVE List V5 official records.
- **NVD (National Vulnerability Database)**: CVSS severity ratings (v2, v3, v4), publication dates, and CWE linkages.
- **CISA KEV (Known Exploited Vulnerabilities)**: Explicit catalog of vulnerabilities with documented active in-the-wild exploitation. KEV membership confirms exploitation exists; it does **not** prove compromise in the target environment.
- **FIRST EPSS (Exploit Prediction Scoring System)**: Probabilistic daily score (0.0 to 1.0) and percentile (0.0 to 1.0) predicting likelihood of weaponization in the next 30 days. Intrinsic score, not asset-specific risk.
- **MITRE ATT&CK (v17.1)**: Adversary Tactics, Techniques, and Common Knowledge.
- **MITRE CWE & CAPEC**: Common Weakness Enumeration and Common Attack Pattern Enumeration and Classification.
- **OSV (Open Source Vulnerabilities)**: Ecosystem-specific package vulnerability records.
- **Curated CAG**: Versioned NIST 800-61r2, OWASP Top 10 (2021), and FIRST CSIRT operational guidance.

## 2. Evidence Taxonomy (`SourceType` & `EvidenceStatus`)

Defined in `src/vera/domain/enums.py` and `src/vera/domain/evidence.py`:

### Source Types (`SourceType`)
- `cag`: Stable, versioned curated knowledge documents.
- `cve_org`: Official CVE Record API.
- `nvd`: NIST NVD API v2.
- `cisa_kev`: CISA KEV JSON dataset.
- `first_epss`: FIRST EPSS API score lookup.
- `mitre_attack`: MITRE Enterprise ATT&CK matrix.
- `cwe`: MITRE CWE weakness catalog.
- `capec`: MITRE CAPEC attack patterns.
- `owasp`: OWASP Top 10 standards.
- `nist`: NIST SP guidelines.
- `osv`: Open Source Vulnerabilities database.
- `stream`: Ingested JSON/JSONL event stream or extracted PCAP telemetry.
- `memory`: Previous conversational turns or historical session runs.
- `web`: External real-time search context (Brave Search).

### Evidence Status (`EvidenceStatus`)
- **`AVAILABLE`**: The evidence item was successfully retrieved and is available for factual quotation.
- **`UNAVAILABLE`**: The source was offline, disabled (`VERA_LIVE_SOURCES=false`), rate-limited (HTTP 429), or returned no record for the requested identifier.
- **`SIMULATED`**: The evidence item originates from synthetic logs or event replays marked explicitly with `simulated: true`.

## 3. Claim Validation Semantics (`ClaimStatus`)

Every assertion in a draft analysis is parsed into a structured `Claim` object with an evidentiary status:

| Claim Status | Meaning & Validation Rule |
| :--- | :--- |
| **`SUPPORTED_FACT`** | An authoritative claim supported by at least one valid `Citation` pointing to available non-memory evidence. Must satisfy verbatim quotation check and >=55% token coverage. |
| **`SYSTEM_INFERENCE`** | Conclusions generated by VERA's rule detectors, event statistics, correlation logic, or knowledge-graph inferences. |
| **`SIMULATED`** | Claims derived from events or streams that were flagged as simulated data. |
| **`UNAVAILABLE`** | Statements regarding missing, unreachable, or unconfirmed security intelligence (e.g. "No KEV record exists for CVE-XXXX"). |

### The Citation Contract (`Citation`)
```python
class Citation(BaseModel):
    evidence_id: str           # Must match an existing item in state["evidence"]
    supporting_quote: str      # Exact, verbatim substring from evidence.content
```
- Citations with fabricated `evidence_id`s or quotes that do not appear verbatim in `evidence.content` are immediately rejected.
- Quotes cannot be taken from `SourceType.MEMORY`.

## 4. Event Stream Detection Rules

Defined in `src/vera/stream/detectors.py` and configurable via `Settings`:

1. **Horizontal / Vertical Service Port Scan**:
   - `port_scan_threshold`: 10 unique target ports.
   - `port_scan_window_seconds`: 60 seconds.
   - Rule ID: `rule:port_scan` (Severity: `MEDIUM`).
2. **Authentication Brute Force**:
   - `auth_failure_threshold`: 5 HTTP/SSH authentication failures.
   - `auth_failure_window_seconds`: 300 seconds (5 minutes).
   - Rule ID: `rule:auth_brute_force` (Severity: `HIGH`).
3. **SYN Flood Burst**:
   - `syn_burst_threshold`: 20 SYN packets without corresponding ACK.
   - `syn_burst_window_seconds`: 10 seconds.
   - Rule ID: `rule:syn_burst` (Severity: `HIGH`).
4. **Application Exploit Markers**:
   - Path Traversal: `../` or `..\\` sequences (Severity: `HIGH`).
   - Command Injection: Unescaped shell delimiters `;`, `|`, `&`, `&&` (Severity: `HIGH`).
   - JNDI Lookup: `${jndi:ldap:...}` or `${jndi:rmi:...}` (Severity: `CRITICAL`).

> [!IMPORTANT]
> Any detection with severity `HIGH` or `CRITICAL` automatically triggers conditional human review (`ReviewRecord`), preventing autonomous publication of incident alerts without human oversight.
